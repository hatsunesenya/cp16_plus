# 版本号没变的原因与修复（B0.1.5）

> 现象：卸载旧的、装上新的，主界面左上角仍显示 **β0.1.3**。

## 一、包里的版本号是对的

```
dist\cp16plus-B0.1.5-261123\cp16plus.exe      含 β0.1.5 = True   含 β0.1.4 = False
dist\cp16plus-B0.1.5-261123-安装包.exe         含 β0.1.5 = True   含 β0.1.4 = False
```

界面文案（`ui.html`）与 `Cargo.toml` 都是 0.1.5，构建产物里也确实写进去了。
所以问题不在"版本号忘改"，而在**新版本没有真正跑到你面前**。

## 二、两个真实缺陷（这才是根因）

### 缺陷 1：安装器静默跳过被占用的文件

```rust
// 旧代码
if fs::write(&path, data).is_ok() { written += 1; }   // 失败就当没发生
```

如果旧版引擎还在后台跑，`cp16plus.exe` 被占用，`fs::write` 失败 →
**这个文件被跳过，其余文件照写，安装器不报任何错**。
结果：目录里留着旧 exe，新装的壳子（快捷方式、版本号）却都是新的。

**修**：安装开始前 `taskkill /F /IM cp16plus.exe`；
写完统计失败文件，杀一次进程后重试；仍失败就弹出明确列表
（"有 N 个文件写不进去（被占用），请先结束 CP16+ 进程再重装"），不再静默。

### 缺陷 2：启动器不看版本就复用旧引擎

```rust
// 旧代码：端口上有我们的引擎就直接开窗
for p in PORT_BASE..PORT_BASE+30 {
    if is_our_engine(p) { 打开 http://127.0.0.1:p/ ; return }
}
```

旧引擎只要还在跑（比如它没被卸载干净、或用户从旧快捷方式启动过），
新装的启动器就**直接把窗口连到旧引擎**——画面上当然是旧版本、旧行为。

**修**：`/api/ping` 里带 `version`，启动器与之比对：

- 版本一致 → 复用（不重复起引擎）；
- 版本不一致 → **不复用**，自己在下一个空闲端口起新引擎。

实测（用一个假"0.1.3 引擎"占住 8770，运行 0.1.5 启动器）：

```
端口 8770 -> version 0.1.3   ← 旧的，没被复用
端口 8771 -> version 0.1.5   ← 启动器自己起的
```

## 三、版本号为什么跳到 B0.1.5

因为 B0.1.4 已经发出去过（虽然 UI 显示不正确），沿用同名会分不清哪份是修好的。
B0.1.5 的启动器才带"版本校验"，所以必须和 B0.1.4 区分开。

## 四、你这边怎么装（重要）

1. 打开任务管理器 → 详细信息，结束所有 `cp16plus.exe` 与 `CP16+ B0.1.x.exe`；
2. 卸载旧版（设置 → 应用 → CP16+，或目录里的 `卸载 CP16+ B0.1.x.exe`）；
3. 装 **B0.1.5**；
4. 打开后左上角应显示 **β0.1.5**。

如果还是旧版本号，说明还有旧进程活着——从 B0.1.5 起，即使出现这种情况，
启动器也会避开旧引擎、另开一个端口，界面显示的仍是新的 β0.1.5。

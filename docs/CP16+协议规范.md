# CP16+ 协议规范（v1）

CP16+ 是一种**用频谱"写"汉字**的低速业余无线电协议：发送端把文字排成 16×16 点阵，
用 16 个等间距音频单音把它"画"在频谱上；接收端不需要解调，**人眼盯着瀑布图就能读字**。
机读层只负责呼号、网格、参数等元信息，不承载正文。

- 协议版本：**v1**（含 v1.1 同步帧）
- 频段：音频域 450–1250 Hz，可经任意 SSB 收发信机发射
- 典型速率：每字 0.7–5.4 s（取决于档位）
- 参考实现与本规范同步维护；本文只描述"当前是什么"，不涉及实现细节与历史。

---

## 1. 为什么这样设计

| 特点 | 含义 |
|---|---|
| **人眼可读** | 正文不经过解码器。只要瀑布图看得清，就能读；不依赖信噪比门限、不需要纠错成功 |
| **单通道** | 只占一段音频带宽（默认 400 Hz），任何 SSB 电台 + 声卡即可 |
| **抗弱信号退化平缓** | 信号弱时字迹变淡，而不是"突然读不出"；配合重复档位可继续抄收 |
| **机读层只带参数** | 呼号/网格/字符数/档位等由控制信道传送，正文永远只走视觉层 |
| **可与语音共存** | 频率安排在语音通带内，听到人声不妨碍看字 |

## 2. 频谱结构

```
       450        620        800 ─────────── 1175   1250
        │          │          │                 │      │
   ─────●──────────●──────────●─●─●─●─ … ─●─●─●────────●─────  Hz
      P1 导频   控制信道 CC   16 个视觉音（间隔 25 Hz）  P2 导频
                 （DQPSK）
```

| 频段 | 用途 | 说明 |
|---|---|---|
| 450 Hz | 导频 P1 | 连续、等幅、不调制 |
| 500–740 Hz | 控制信道 CC | 载波 620 Hz，占用 ≤ 240 Hz |
| 740–800 Hz | 保护带 | 不发射 |
| 800–1175 Hz | **视觉层** | 16 个音，间隔 25 Hz（第 i 个音 = 800 + 25·i） |
| 1175–1250 Hz | 保护带 | 不发射 |
| 1250 Hz | 导频 P2 | 与 P1 相距 800 Hz（＝32 个音间隔），用于频轴标定 |

**相对电平**（RMS，以视觉层单音为 1.00）：控制信道 0.60 ± 0.05，每根导频 0.31 ± 0.05，
整段峰值不超过 0.99。

**共存布局**（可选，整体压到 1000 Hz 以下，便于躲开数据模式）：P1 350 Hz、
控制信道载波 500 Hz、视觉层 640 Hz 起、间隔 18.75 Hz、P2 960 Hz。使用时在帧头注明布局。

## 3. 时间结构

```
|导频 1.5 s| HDR | gap 0.1 s | 字符单元 × n | gap | EOT | 尾巴 0.5 s |
```

一个**字符单元** = 1 行边距 + 16 行字形，每行重复 R 次，共 `(16+1)·R` 行。

一行的时间 `T_row` 由档位决定，且必须满足 `k = Δf · T_row` 为整数
（这样一行恰好等于 5k 个控制信道符号，接收端才能用 CC 锁定行定时）。

| 档位 | 音数 N | 间隔 Δf | k | 行时长 T_row | 单字时长 | 占用带宽 |
|---|---|---|---|---|---|---|
| M1 | 16 | 25 Hz | 1 | 40 ms | 0.68 s | 400 Hz |
| **M2（默认）** | 16 | 25 Hz | 2 | 80 ms | 1.36 s | 400 Hz |
| M4 | 16 | 25 Hz | 4 | 160 ms | 2.72 s | 400 Hz |
| M8 | 16 | 25 Hz | 8 | 320 ms | 5.44 s | 400 Hz |
| 16N-M4（共存） | 16 | 18.75 Hz | 4 | 213 ms | 3.63 s | 300 Hz |
| 24-M4（清晰） | 24 | 25 Hz | 4 | 160 ms | 4.00 s | 600 Hz |

**垂直重复 R** ∈ {1,2,3}：同一行连发 R 次，字时长乘以 R，用于弱信号下"描粗"字迹。

## 4. 视觉层：怎么把字画上去

1. **映射**：取字符的 16×16 点阵。字形第 `r` 行、第 `i` 个像素为 1 时，
   在第 `r` 行的时间片内以 `f_i = f_lo + i·Δf` 发一个单音；为 0 则不发射。
   由此，时间轴 = 字形的横轴，频率轴 = 字形的纵轴，瀑布图上看到的就是正立的一个字。
2. **包络**：每个音独立键控，开关处有升余弦过渡（约 `0.03·T_row`），
   同一音连续亮多行时不产生相位或包络跳变。
3. **初相**：每个音一个随机初相，整段固定不变。
4. **边距行**：每个字符的第 0 行，16 个字形音全部静音，只在 `f_lo − 2Δf`
   发一个短音（占该行前 40%，幅度为字形音的 1.6 倍）。它是人眼和软件判定
   "字从这里开始"的锚点。
5. **功率**：行内各音等幅（不做逐行归一化），便于人眼按亮度判断信号强弱。

---

## 5. 字库

- 点阵：16×16，与常见 HZK16 一致；覆盖 GB2312 全部 7445 个汉字及全角符号。
- 容器格式 `CPF1`：

```
"CPF1" | 版本 u8 | 点阵尺寸 u8(=16) | 字数 u32 | 标志 u16 |
字数 × (码位 u16, 偏移 u32) | 点阵数据（每字 32 字节，按行，每行 2 字节）
```

- 半角 ASCII 不在字库内：正文中的 ASCII 应当先转成全角再发送，
  这样每个字符都是 16×16 点阵，节奏一致。

## 6. 控制信道（机读层）

| 项 | 值 |
|---|---|
| 调制 | DQPSK，符号率 125 Bd（8 ms/符号），载波 620 Hz |
| 成形 | 根升余弦，α = 0.35，跨度 8 符号，收发各一次 |
| 纠错 | 卷积码 K=7、码率 1/2（生成多项式 0171/0133），软判决 Viterbi，6 bit 归零 |
| 交织 | 块交织，长度等于码字长度 |
| 校验 | CRC-16/CCITT-FALSE |

**帧类型**

| 帧 | 净比特 | 突发长度 | 位置 |
|---|---|---|---|
| HDR（报文头） | 165 | 203 符号（1.62 s） | 导频之后 |
| BCON（续传/计数） | 62 | 100 符号（0.80 s） | 每 8 个字符之后 |
| EOT（结束） | 16 | 54 符号（0.43 s） | 正文字符之后 |

**HDR 字段**（MSB 先出，共 165 bit，含 CRC-16）

| 字段 | 位 | 说明 |
|---|---|---|
| MAGIC / VER | 16 / 4 | `0x4350`（"CP"）/ 1 |
| MODE | 10 | 栅格（16 或 24 音）· k · R · 字库号 |
| CALL | 36 | 6 字符 × 6 bit（A–Z 0–9 / 空格） |
| GRID | 30 | 6 字符梅登黑德网格 |
| LEN | 10 | 字符数 |
| TYPE | 3 | 0=CQ 1=QSO 2=紧急 3=公告 4=呼号 5=测试 |
| SF_ID / UTC / PWR | 12 / 11 / 3 | 超帧号 / 当日分钟 / 功率档 |
| RMAP | 8 | 重复图位掩码 |
| PLAN | 2 | 0=默认布局，1=共存布局 |

## 7. 同步帧（v1.1，每 10 秒一帧）

控制信道最初只在报文开头出现一次 HDR：晚开机、或在开头遇到一次深衰落，就再也拿不到参数。
v1.1 因此加入**周期同步帧**，把参数从"一次性"变成"每 10 秒刷新"。

- 周期 **10 s**，按 **UTC 整十秒对齐**（帧起始符号落在 `t mod 10 = 0`）。
- 一帧 104 信息比特 → 208 编码比特 → 104 个 QPSK 符号 → **0.832 s**。
- 与视觉层**频分共存**，不占用视觉层的时间。
- 使用第三套 32 符号前导（种子 `0xC3`），与 HDR 的 A、BCON/EOT 的 B 互不相关，
  因此老接收端会把它当噪声忽略——这是无损向后兼容的关键。

| 字段 | 位 | 说明 |
|---|---|---|
| MAGIC | 8 | 固定 `0xC5`，用于快速判伪 |
| SLOT | 6 | `UTC 秒 / 10` 取模 60，由发送端写入（接收端不依赖本地时钟） |
| CELL | 16 | 本时隙起点之后第一个字符的序号 |
| CALL_CRC8 | 8 | 呼号校验，用于把视觉层与本帧关联 |
| GRID | 30 | 6 字符网格（A–R 字母表） |
| MODE | 10 | 栅格 8 bit + k 2 bit |
| FONT_ID | 4 | 字库编号 |
| RSV / CRC | 6 / 16 | 保留 / CRC-16（覆盖前 88 bit） |

有了同步帧，接收端可以：晚加入（等下一个 10 秒）、失锁后自动恢复、
在两次同步帧之间**滑行**（用上一次的参数继续读字，最多容忍丢失 3 帧）。

## 8. 接收端要点

**软件解（机读层）**

1. 频轴标定必须由 P1/P2 解出实测映射 `f_meas = a·f_nom + b`，不要在频谱上盲搜音位置。
2. 行定时用控制信道**锚定**：一行恰好等于 5k 个 CC 符号；每段字符的起点 =
   前一个突发起点 + (突发符号数 + 15) 个符号；之后按行递推，允许 ±2 行的整行微调。
3. 残余定时误差应小于 2% 行时长（实测 2% 时鬼影约 −28 dB）。
4. 长时间丢同步时退回相位搜索，并在界面上标注"降级"。

**人眼解（视觉层）**

1. 瀑布图上，纵轴是频率、横轴是时间；一个字占 16 行（横轴 16 格），
   行内的亮点组成字的笔画。
2. 每个字开头那条**低于 16 音区的短亮线**是边距音，用它对齐字头。
3. 读不出字时优先加长档位（M4/M8）或把重复 R 调到 2–3，让笔画变粗。
4. 亮度只代表信号强弱，不影响 0/1 判定；灰淡但结构清楚的字仍然可读。

## 9. 兼容性与版本

| 项 | 说明 |
|---|---|

## 一、协议：CP16+ 相对早期设计的主要变化

CP16+ 保留了"人眼直接从瀑布图读汉字"的核心，改的是承载它的骨架：

| 项目 | 早期做法 | CP16+ |
| --- | --- | --- |
| 速率 | 固定 | 档位化：`k = Δf·T_row` 必须为整数，M1/M2/M4/M8 四档（单字 0.68–5.44 s），另有两种共存布局 |
| 参数下发 | 报文头一次性 | 报文头之外增加**每 10 秒一帧同步帧**（含字符计数、呼号校验、档位），支持晚开机、失锁恢复与滑行 |
| 纠错 | 无 | 控制信道 DQPSK + 卷积码 K=7/r=1/2 + 块交织 + CRC-16 |
| 定时 | 接收端自行搜索 | 双导频（450/1250 Hz）频轴定标 + 控制信道锚定行定时（"一行 = 5k 个符号"），误差 < 2% 行时长 |
| 字库 | 各自约定 | CPF1 容器：16×16 点阵，覆盖 GB2312 全部 7445 字，与字符集解耦 |
| 兼容 | — | 与 CP16、CP16E 帧结构不同、互不识别；v1.1 同步帧对 v1.0 接收端无损（用第三套前导，老接收端会当噪声忽略） |

由此带来三点实际收益：**弱信号下退化平缓**（字迹变淡而不是整段丢失）、**可以中途加入**（不必等报文头）、**收发频偏可精确标定**（不依赖"猜"音位置）。

## 二、软件：面向爱好者的实现

配套软件为 Windows 桌面程序，主要功能：

- **接收**：选声卡输入即可实时出图，肉眼读字；控制信道自动带出呼号与网格；右侧"存档区"保留最近若干个 10 秒块，不暂停也能回看。
- **发射**：报文输入 + 点阵预览，按 UTC 整十秒对齐播出，可随时中断；ASCII 自动转全角以匹配 16×16 字库。
- **原始瀑布图**：独立窗口，横轴频率、时间自上而下流（与 SDR 软件一致），用于确认设备状态、以及在主界面判读困难时人工读取。
- **电台联动**：通过 Hamlib（与 JTDX 同源）支持 260 余种型号的 CAT 频率读写与自动 PTT，含发射前提前量、发射中 PTT 保活、退出时释放。
- **通联日志**：呼号/网格/频率逐条记录，导出标准 ADIF 3.1.4，可直接导入常用日志软件。

实现上刻意保持"轻依赖"：Rust 编写单一引擎（采集、DSP、编解码、内置 HTTP 服务与界面分发），界面用系统已有的 Edge/Chrome 以应用窗口方式呈现，因此不需要 .NET、Node 或联网；调制解调、FFT、维特比译码均为自研代码，第三方依赖仅一个声卡库与运行期动态链接的 Hamlib（LGPL-2.1，可自行替换）。协议另附一份 Python 参考实现，与 Rust 实现做逐位对拍，回归脚本覆盖同步、鲁棒性、SNR 扫描。

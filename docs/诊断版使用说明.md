# 诊断版使用说明（B0.1.2-261123 · 修正版）

> 上一个诊断包有两个问题，已修：
> 1. **诊断包按钮导出的是空对象**——`api()` 返回的是 `Response`，代码忘了 `.json()`，于是 `行数据`/`状态` 都是 `{}`；
> 2. **接口"not found"**——你当时打开的是仍占用 **8770** 的旧版引擎，诊断版被挤到了 8771。
>
> 现在诊断版有**自己的端口段 8791 起**，界面标题也会显示"**诊断版**"，不会再和正式版混淆。

## 怎么用（推荐顺序）

### 方案 A：用你已经在跑的那个诊断版（不用换包）

你现在的诊断版引擎占的端口是 **8770**（因为旧的已经关掉了）。接收状态下用浏览器打开：

```
http://127.0.0.1:8770/api/debug/rows
```

看到 JSON（很长一行）就说明对了，全选复制发我。
如果显示 `not found`，依次试 `8771`、`8772`，直到出现 JSON。

### 方案 B：用这个修正版包

1. 解压到任意目录，双击 `CP16+ B0.1.2.exe`
2. **确认标题栏/左上角显示"诊断版"**（这是判断你打开的是哪个版本的唯一可靠标志）
3. 开始接收，播 `examples\示例-长报文25字.wav`
4. 播完先别停止，点右上 **DEBUG** → **诊断包**，下载 `cp16plus-诊断-*.json` 发我

诊断版地址固定在 `http://127.0.0.1:8791`。

## 这个 JSON 里有什么

| 字段 | 含义 | 正常值 |
|---|---|---|
| `rows` | 最近 64 行解调结果，每行 16 个数 | 有字时应是"0 / 某值"两态 |
| `est.a` / `est.b` | 双导频标定出的频率缩放与偏移 | `a≈1.00`、`b≈0` |
| `tones` | 解调实际使用的 16 个音频率 | 从 `800` 起、步进 `25` |
| `t_row` | 一行的采样点数 | 8 kHz + M2 时约 `640` |
| `spec` | 0–4000 Hz / 512 点平均频谱（dB） | 峰值落在 800–1200 与 450/1250 |
| `fs_in` / `channels` / `device` | 声卡采样率、声道、设备名 | 例如 `48000 / 2` |
| `mode` | 解调档位 | `M2` 或 `hdr` |

## 我会据此判断的两件事

1. **导频标定是否偏**：`est.a`≠1 或 `b` 很大 → 16 个音解到错误频率 →
   画面只剩"前面几个音"一块色块（和你截图一致）。
2. **行定时是否偏**：`t_row` 远离 640 → 取样错位、字形被抹平。

两者都不需要你再反复试，看一眼 JSON 就能定。

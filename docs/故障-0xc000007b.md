# 启动失败 0xc000007b 的排查与修复

> 现象：装好后双击，弹出"应用程序无法正常启动(0xc000007b)。请单击"确定"关闭应用程序"。
> 这是 **Windows 加载器**报的错（`STATUS_INVALID_IMAGE_FORMAT`），不是程序自己的报错——
> 说明某个被依赖的 DLL 位数不对、损坏，或者根本找不到。

## 为什么会发生

`cp16plus.exe`（64 位）在启动时要加载 `libhamlib-4.dll`（电台 CAT 用），
而 Hamlib 又依赖两个 DLL：

```
cp16plus.exe (x64)
  └── libhamlib-4.dll (x64)
        ├── libusb-1.0.dll      (x64)
        └── libwinpthread-1.dll (x64)
```

只要其中任何一个被换成 **32 位版本**，或者文件被截断/杀软隔离，加载器就会报 0xc000007b。
常见来源：

| 可能原因 | 说明 |
|---|---|
| **32 位同名 DLL 抢先被找到** | 机器上装过 32 位的其他软件（老日志软件、SDR 程序、旧版 JTDX），把 32 位的 `libusb-1.0.dll` / `libwinpthread-1.dll` 放进了 `C:\Windows\System32` 或某个 PATH 目录 |
| **安装目录里缺这两个 DLL** | B0.1.1 及更早的安装包只带了 `libhamlib-4.dll`；在老 JTDX 机器上碰巧能找到依赖，在干净机器上就会出问题 |
| **杀毒软件隔离/截断** | 安装完立刻被拦，DLL 变成 0 字节或不完整 |
| **文件传输损坏** | 用 U 盘/网盘拷绿色版时中途断了 |
| **32 位 Windows** | 本程序只有 64 位版本 |

## 第一步：跑一遍诊断脚本

把 `诊断-启动失败.ps1` 放到安装目录（默认 `C:\Program Files\CP16Plus`），右键
"使用 PowerShell 运行"，或用命令：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "C:\Program Files\CP16Plus\诊断-启动失败.ps1"
```

它会把下面这些信息一次列出来，贴回群里就能定位：

- 系统位数、Windows 版本
- 安装目录里每个 DLL 的**位数**与大小
- `libusb-1.0.dll` / `libwinpthread-1.dll` 在 PATH / System32 里的副本及其位数
- 是否被标记为"来自其他计算机"（MOTW，可解阻止）

## 第二步：按结果处理

### A. 诊断显示某个 DLL 是 32 位 → 换成本程序自带的 64 位版本

1. 从**安装包**重新装一遍（B0.1.2 起已随包附带 `libusb-1.0.dll`、`libwinpthread-1.dll`）。
2. 如果装完仍是 32 位，说明系统里有个 32 位副本被优先加载：
   - 用诊断脚本给出的路径定位它（通常在 `C:\Windows\System32` 或 PATH 里某个目录）；
   - 属于别的软件的**不要删**，把它所在目录从 PATH 里移出，或把本程序装到一个**独立目录**
     （例如 `D:\CP16Plus`）后再试——Windows 会先找程序自己目录里的 DLL。

### B. 诊断显示 DLL 缺失或 0 字节 → 重装 / 解隔离

1. 打开 `Windows 安全中心 → 病毒和威胁防护 → 保护历史记录`，看有没有拦截记录，恢复并加入排除项。
2. 重新运行安装包（或重新解压绿色版 zip），确认安装目录里有这 4 个文件：
   `libhamlib-4.dll`、`libusb-1.0.dll`、`libwinpthread-1.dll`、`cp16plus.ico`。

### C. 文件被标记为"来自其他计算机"

绿色版从网上下载后可能带 MOTW。安装目录里执行（管理员 PowerShell）：

```powershell
Get-ChildItem "C:\Program Files\CP16Plus" | Unblock-File
```

### D. 系统是 32 位

`系统信息 → 系统类型` 显示 "32 位操作系统" 时，本程序无法运行；需要 64 位 Windows。

## 第三步：还不行的定位方法

1. **看是哪个程序报错**：任务管理器里如果 `cp16plus.exe` 一闪而过、只剩启动器窗口，就是引擎被拦。
2. **手动启动引擎**，把完整报错留下来：

   ```powershell
   cd "C:\Program Files\CP16Plus"
   .\cp16plus.exe serve --port 8770 --no-open
   ```

   - 报 `0xc000007b` → 仍是 DLL 位数/损坏问题，回到 A/B；
   - 报"找不到 libhamlib-4.dll" → 安装不完整，重装；
   - 能起来但页面空白 → 与本错误无关，看 `设置 → DEBUG` 日志。

3. **临时绕过电台功能验证主程序**：把 `libhamlib-4.dll` 及其两个依赖临时改名，
   引擎会以"没有链接 Hamlib"的方式启动（电台页显示不可用），但收发、瀑布、日志都能用。
   这能快速区分"是 Hamlib 依赖问题"还是"程序本身问题"。

## 我们这边的修复（B0.1.2 起）

- 安装包与绿色版**都附带** `libusb-1.0.dll`、`libwinpthread-1.dll`（均为 64 位），
  与 `libhamlib-4.dll` 放在同一目录。程序目录优先于 System32/PATH，因此不会再被
  机器上的 32 位副本顶掉。
- 之前之所以没暴露：开发机上装了 JTDX，`C:\JTDX64\159\bin` 在 PATH 里，
  这两个依赖正好被找到。干净机器上就会失败——这是打包遗漏，已在 B0.1.2 修正。

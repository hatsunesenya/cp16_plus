# 杀软误报（360 等）与代码签名

> 结论先说：**没有加壳**。误报主要来自三件事——安装器是"自解压 + 释放执行"、
> 早期版本用 `powershell -EncodedCommand`（base64 命令行，杀软头号特征）、以及**没有签名**。
> B0.1.2-261108 起前两项已从程序里彻底去掉，第三项需要证书。

## 一、为什么会被判毒

| 行为 | 杀软怎么看 | 现状 |
|---|---|---|
| 14 MB 的 exe 尾部带一大块非 PE 数据，运行时释放文件并执行 | 典型"自解压释放器"特征 | 仍保留（标准安装包做法），但**新增了免自解压的安装方式** |
| `powershell -EncodedCommand <base64>` | 编码命令行＝加载器/木马常用手法 | **已删除**：改用原生 Win32 窗口与 COM 创建快捷方式 |
| 写 `Program Files`、建快捷方式、写 HKLM 卸载项 | 安装器正常行为，但配合"未签名"会叠加 | 保留（这是安装包该做的事） |
| 引擎监听 `127.0.0.1` 端口、拉起 Edge/Chrome | 少数启发式会标记"后门/浏览器劫持" | 保留（本地服务 + 应用窗口是本软件的架构） |
| 可执行文件无数字签名、下载量小 | "未知发布者"，声誉分为 0 | **需要证书**，见第三节 |

另外确认一点：我们**没有**用 UPX 之类加壳工具，exe 是 rustc 直接产出的普通 PE。
"加壳"这个判断可以排除——真正的问题是"未签名的自解压安装器"。

## 二、现在的三个发行形态（按误报概率从低到高）

| 形态 | 文件 | 说明 |
|---|---|---|
| 绿色版 | `cp16plus-B0.1.2-<日期>.zip` | 解压即用，不写注册表、不要管理员。**最不容易被拦**，推荐先给怕杀软的朋友用 |
| 免自解压安装包 | `cp16plus-B0.1.2-<日期>-安装包-免自解压.zip` | 解压后运行 `安装程序.exe`：它不带载荷，从同目录复制文件安装。没有"释放执行"那一步 |
| 标准安装包 | `cp16plus-B0.1.2-<日期>-安装包.exe` | 单文件自解压，三步协议页 + 选目录，最方便，也最容易被启发式盯上 |

## 三、彻底解决：代码签名

签名后：SmartScreen 不再提示"未知发布者"，360/火绒等的"未知程序"判定会显著下降；
被误杀时申诉也更容易通过。

1. **买证书**：代码签名证书（OV 约 200–400 元/年；EV 更贵但信誉最好，需要 USB Key）。
   个人开发者可选 Certum / Sectigo 的"Open Source Developer"低价证书（需开源项目证明）。
2. **签名**（Windows SDK 装 "Signing Tools" 后）：

   ```powershell
   # 证书在个人存储里
   .\tools\sign.ps1 -Thumbprint <证书指纹> -Files "dist\cp16plus-B0.1.2-261108\*.exe"

   # 或者用 pfx
   .\tools\sign.ps1 -Pfx .\cert.pfx -Password "***" -Files "dist\cp16plus-B0.1.2-261108\*.exe"
   ```

   脚本会对目录里每个 exe（启动器、引擎、安装器、卸载器）做 SHA-256 时间戳签名并验签，
   最后打印 SHA-256 供发布页使用。
3. **顺序很重要**：先构建 → 再签名 → 最后打包 zip；否则 zip 里的 exe 还是未签名的。
   （自带载荷的安装包要在"追加载荷"之后签，否则签名会被破坏。）

## 四、被误报后的处理

1. **先让用户核对哈希**：发布页贴上 `SHA256`，用户本地 `Get-FileHash` 一致就不是下载被篡改。
2. **加入信任**：360 → 木马查杀 → 信任区；或右键文件 → "添加信任"。这只是绕过，不解决根因。
3. **提交误报申诉**（免费，通常 1–3 个工作日）：
   - 360 误报申诉：<https://open.360.cn/report.html>（选"文件误报"）
   - 火绒：论坛"误报反馈"版块
   - Microsoft：<https://www.microsoft.com/en-us/wdsi/filesubmission>（选 Software developer）
   - VirusTotal：上传后可在"Details → Comments"里说明，并用各家厂商的 false-positive 表单
4. **申诉时附上**：文件哈希、下载地址、源码仓库地址、说明"开源业余无线电软件，无网络回连，
   仅本地 127.0.0.1 服务"。把 `docs/CP16+社区介绍.md` 的内容贴一段也行，有助于判定。

## 五、还能进一步降误报的做法（按性价比排序）

1. **签名**（唯一能根治的）。
2. **提高下载量与知名度**：声誉分是逐步累积的，发布页固定域名 + 稳定文件名有帮助。
3. **避免单文件自解压**：优先推绿色版与"免自解压安装包"。
4. **版本信息（VERSIONINFO）已加上**：公司名 `BD8DQS`、产品名 `CP16+ 频谱书写`、
   文件版本 `0.1.2.0`、版权 `Copyright (C) 2026 BD8DQS. MIT License.`，
   引擎/启动器/安装器/卸载器都带，属性页里能直接看到发布者，不再是"无信息裸 exe"。
5. **提交 VirusTotal 并公开链接**：让用户自己看到 70 家里只有个别误报，比任何口头解释都有力。

## 六、本次改动清单（B0.1.2-261109）

- 安装器不再调用 PowerShell：协议/许可页改为原生 Win32 窗口（只读多行 EDIT + 两个按钮），
  快捷方式改为 `IShellLink` COM 创建 —— 安装过程中**零脚本、零子进程**。
- 新增"免自解压"安装包：`安装程序.exe` + 同目录文件，去掉"释放执行"特征。
- 随包附带 `libusb-1.0.dll`、`libwinpthread-1.dll`（修复 0xc000007b，见另一份文档）。
- 新增 `tools/sign.ps1`（签名 + 验签 + 打印哈希）。
- 新增 `tools/stamp_version.ps1`：给三个 exe 写入 VERSIONINFO（公司名 `BD8DQS`），
  构建脚本自动调用并回读校验。
- 暂不做数字签名（证书成本考虑）；如需彻底解决 SmartScreen 提示，仍需签名证书。
